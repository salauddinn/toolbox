# Detect broadly and automate narrowly

ToolBox will detect and explain multiple evidence-backed Modernization Findings, but the MVP will automate only behaviour-test generation with an existing supported harness, Domain Module separation and one conditional circular-dependency repair. Shared-model ownership, global state, unsupported cross-domain access, a missing test harness and dependency age remain visible findings with guidance when ToolBox cannot transform and validate them safely.

## Consequences

Every finding is labelled as automatable or developer-decision-required. Product language and UI must never imply that detection guarantees automatic remediation, and additional automatic repair types remain stretch work until the locked workflow is complete.
